# Contributing

Thanks for helping with this hackathon project. Keep changes small, focused, and easy to review.

## Workflow

1. Create a branch from `main` (`feature/...`, `fix/...`, or `docs/...`).
2. Make your changes with clear commits.
3. Open a pull request using the PR template.
4. Get at least one teammate review before merging (when possible).

## Local setup

1. Copy `.env.example` → `.env` and add your keys.
2. Install dependencies.
3. Run the app with the project start script (see `README.md`).

## Guidelines

- Prefer small PRs over large dumps.
- Do not commit secrets, API keys, or `.env` files.
- Update docs when behavior or setup steps change.
- Add or update tests when you change core logic.
- Keep naming clear; avoid clever abbreviations.

## Commit messages

Use short, imperative messages:

- `add voice session endpoint`
- `fix mic permission handling on Safari`
- `update submission checklist`

## Questions

Ask in the team chat or open a draft PR with notes for discussion.
